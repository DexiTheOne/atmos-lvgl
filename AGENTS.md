# Project policy: develop the LVGL implementation

The native LVGL application in `desktop/` is the source of truth for the product UI. From now on, implement rendering, layout, animation, navigation, and sensor/history changes there by default. A request to change "the rendering", "preview", "animation", or "UI" means the LVGL simulator unless the user explicitly says otherwise.

The root `index.html`, `app.js`, `style.css`, and `server.mjs` are the original browser design reference. Consult them to recover design intent, but do not implement requested product changes only in those files or maintain a second browser implementation. Edit the browser reference only when the user explicitly requests it. A future browser preview should display actual LVGL output and forward controls to the native model.

## Code map

- `desktop/atmos.c`: platform-independent C UI, LVGL drawing, sensor simulation, history, scene navigation, and transition composition.
- `desktop/atmos.h`: UI/model interface, including `atmos_set_readings()` for real sensor data.
- `desktop/main_win32.c`: Windows window, input, frame presentation, snapshots, and native render/presentation verification.
- `desktop/lv_conf.h`: LVGL configuration mirroring what ESPHome generates (see ESPHome integration).
- `desktop/CMakeLists.txt`: native application and CTest setup.
- `desktop/build.ps1`: dependency revision check, configure, compile, test, and optional launch.
- `desktop/render_review.py`: optional Pillow-based transition review sheets and GIFs.
- `desktop/README.md`: detailed runtime and hardware-port notes.
- `desktop/ui_fonts.c`: the UI's 1-bit fonts, generated by `desktop/generate_ui_fonts.py <DejaVuSans-Bold.ttf>` (one copy ships with MSYS2's matplotlib). 12 and 16 px: DejaVu Sans Bold; 24 px and up (titles, badges, readings): Open Sans ExtraBold (`desktop/fonts/OpenSans[wdth,wght].ttf`), its decimal point given half a digit's side bearing; `ui_chart_12` (everything inside history charts, selected by `UI_FONT_AXIS`): Spleen 6x12 (`desktop/fonts/spleen-6x12.bdf`). DejaVu glyphs are FreeType's hinted grey rendering cut at half coverage; Open Sans glyphs are unhinted (8× supersampled, box-averaged), each shifted by the sub-pixel phase (any horizontal, up to a quarter pixel vertical, never moving its top or bottom ink row) that leaves the fewest one-pixel bumps and dents, then remaining one-pixel bumps and dents cleared inside the glyph's box, because Open Sans's hinting left nubs on the 3 and stray steps inside the 4. One bitmap per glyph at whole-pixel advances. The chart font is Spleen emboldened by one pixel. Licences are in `desktop/fonts/`. Do not ship non-free fonts (Verdana, Segoe UI, Tahoma): the repository is public and the firmware is built from it. Regenerate rather than hand-editing.
- `desktop/splash_badge.h`: the packed 1-bit "Made for ESPHome" badge for the boot splash, generated by `desktop/generate_splash_badge.py` from `desktop/assets/`.

Keep Windows APIs in the platform layer. Keep UI/model code reusable for the hardware build. The device firmware is ESPHome: `atmos.c`/`atmos.h` will be wrapped as an ESPHome external component, and ESPHome owns LVGL, the display driver, Home Assistant API, OTA and sensors. The desktop build is not device firmware; do not imply that simulator frame rate or memory allocations have been validated on the physical panel.

## Build and verification

Run PowerShell commands from the project root unless stated otherwise:

```powershell
./desktop/build.ps1
```

Prerequisites: CMake, Git, MSYS2 UCRT64 GCC and `mingw32-make`. The script prepends `C:/msys64/ucrt64/bin` when present. LVGL 9.5.0 is pinned to commit `85aa60d18b3d5e5588d7b247abf90198f07c8a63`, matching `LVGL_VERSION` in the released ESPHome (2026.9.1; ESPHome's dev branch is already on 9.6.0); the first build clones it into `desktop/vendor/lvgl` (with Git long paths), requiring network access. Do not silently upgrade or modify vendored LVGL. When ESPHome changes its LVGL version, move the pin with it: update the tag and commit in `build.ps1`, delete `desktop/vendor/lvgl`, rebuild, and fix any warnings. `CMakeLists.txt` compiles LVGL's C sources directly because LVGL's own CMake (9.6.0 at least) also builds optional C++ glTF sources whose headers are missing from the tag. Generated dependency and build directories are ignored.

The script builds with warnings treated as errors and runs `ctest --test-dir desktop/build --output-on-failure`. Complete these checks after C/configuration/build changes. For documentation-only edits, check the documented commands against the actual scripts; rebuilding is unnecessary.

CTest also runs `atmos --test-intro` (boot splash, then the intro transition onto the first page). CTest invokes `atmos --self-test`: model/history/navigation checks, transition endpoints, a check that every mid-transition frame the display receives equals the composed 1-bit frame, a check that every partial redraw of a still scene equals a full redraw of the same moment (the simulator renders in LVGL direct mode, so partial redraws behave as under ESPHome), actual LVGL frame palette/nonempty checks, and Windows GDI presentation checks. Tests do not establish visual quality or hardware performance. Inspect rendered frames or animation captures when changing appearance or motion, including Good/Fair/Poor scenarios and forward/reverse navigation.

## Launch and operate

Build, verify, and launch with:

```powershell
./desktop/build.ps1 -Run
```

To launch an existing build with a predictable snapshot directory:

```powershell
$simulatorPath = Join-Path (Get-Location) 'desktop/build/atmos.exe'
$simulatorDir = Split-Path $simulatorPath
Start-Process -FilePath $simulatorPath -WorkingDirectory $simulatorDir -WindowStyle Hidden
```

The launcher hides the console; the application explicitly shows its native GUI. Preserve the startup visibility handling. In restricted execution environments, a background process may end with the sandbox job. Use the supported approval/escalation flow when needed to launch a persistent window. After launching, verify that the process is responding and has a nonzero `MainWindowHandle`; do not report that a window opened based only on `Start-Process` succeeding.

If the executable is locked during linking, close only this project's simulator instances, verified by their full executable path, then rebuild and relaunch. Do not terminate unrelated processes by name. A requested rebuild/run authorizes restarting this simulator as necessary.

## Preserve the display and interaction contract

- Layout rules, shared by every page and measured from captured pixels (ink, not font line boxes): titles are centred on capital height in the 30 px badge (title ink y 16–33); content ink spans x 12–387, the same as the header rule; content groups are centred on the band between the header rule and the history panel (y 49–204); stacked label/value/unit rows are `UI_TEXT_GAP` (12 px) apart; rows across columns share baselines; leftover width is split into equal gaps between elements; text is centred with `centered_text()` (ink-based). History charts share one geometry (`chart_geometry()`): no unit or time captions, Y-label ink from x 12, and a "LAST n" pill over the top-right corner. Draw rounded or sloped 1-bit shapes from spans (`pill()`, the chart trace), not anti-aliased LVGL primitives, which lose pixels when thresholded. Re-measure every page after layout changes.
- Wi-Fi: every badge is split into the rating's box and, after a 4 px paper gap, a 35 px box holding a centred paper Wi-Fi icon (`wifi_icon()`, `UI_WIFI_*`), one arc per bar (unlit arcs are not drawn); when disconnected, the arcs as 1 px outlines with a bold 8 px X beside the stem. The rating text is centred in its own box. `atmos_set_wifi()` takes 0-3 bars or -1; the device maps RSSI with `atmos_wifi_bars()` (-60/-70/-80 dBm) each frame, redrawing only on change.
- Readings: values print in full on every page except the CO2 page, which abbreviates from 10000 ("10.0k"); decimals drop at 1000. Fixed text columns are sized by `widest_number()` for the sensor maximums (`UI_SENSOR_*_MAX`), and chart scales never pass those maximums. `atmos.exe --capture-full-scale` captures every page at and just below the maximums; `--capture-hcho` captures the formaldehyde page from 0 to 1000 ppb.
- Display units: temperature (°C/°F) and pressure (hPa/kPa/mmHg/inHg) are display-only (`atmos_set_temperature_unit()`, `atmos_set_pressure_unit()`; the device's `temperature_unit`/`pressure_unit` selects). Readings, rating bands (YAML in SI), alerts, history and the values reported to Home Assistant stay °C and hPa; `shown()` converts at drawing time, for the value text, the overview footer and the chart scale. Climate columns are sized for the widest reading in the selected unit (`shown_widest()`), and the value column moves right off the labels when a unit needs it. `atmos.exe --capture-units` captures the climate page and overview in every unit (`units-*.bmp`). `--capture-pm-presses` replays key presses on the Particles page at the device's 59 ms frame period (`pm-press-NNN.bmp`).
- Overview (`draw_dashboard()`): static and quiet, no motion, history or graphs; it redraws only when readings change (`animated_area(0)` is empty). A 4 × 2 grid of tiles split by 1 px rules (CO2, VOC, NOx, HCHO / PM2.5, PM10, Temp, RH; PM1, PM4 and pressure are left out): tiles are equal (94 × 125 px) and each stacks four rows, all centred on the tile's centre line: a 16 px icon with the short name, the value in the largest font whose widest reading fits every tile (`tile_value_size()`), its unit, then the rating marker on its own row (check = level 0, ringed ! = 1, solid warning triangle = 2+; a band's `mark` overrides it: the comfort bands use snowflake (Cold), star (Cool), sun (Warm), flame (Hot), outlined drop (Dry), drop (Humid), two drops (Damp), 13 px grid bitmaps or sampled drops). Rows are measured by ink and the leftover height is split into five equal gaps (above, between, below). Text rows share baselines across tiles (measured ascender to baseline; descenders such as the p in "ppm" or "Temp" hang into the gap below); names are centred on their capitals beside the icon. Icons and markers are placed by their own ink (`icon_ink_box()`, measured once: the shapes are fixed). Icons follow each page's artwork (the Gases ribbons with the reading's own ribbon thick, the Climate thermometer and droplet). Icons and markers are shapes sampled per pixel and drawn as spans (`icon_ink()`). If the tiles get crowded, drop the icon, never the marker. Tiles sit in a closed grid whose frame has the PM cards' corner radius (`UI_TILE_GRID`). Its exit is the icon handoff (`prepare_overview_effect()`): the destination tile's icon starts that page's own effect, over the still grid (CO2: the icon's bubbles open in turn with ink rims; particles: the PM2.5 and PM10 icons' specks bloom, then the dust storm spreads from both; gases: the page's ribbon runs between the VOC and NOx icons and swells outward from both, across and lane by lane; climate: a droplet falls onto the RH icon; formaldehyde: the icon's oxygen atom iris). Icon positions are recorded when the overview is drawn (`tile_icon_at`). `atmos.exe --capture-transitions` also writes each overview exit (`overview-to-N-frame-NN.bmp`).
- Formaldehyde page (SEN68 HCHO, ppb): the CO2 page's layout. The reading prints with one decimal ("999.9", then "1000" at the 1000 ppb maximum) in the largest font whose widest reading fits the title's ink width. H2CO molecules (C ring, filled O, two H rings) drift and spin in the field to its right; their number rises from one near zero to all ten at `UI_HCHO_FULL` (the 1000 ppb maximum) on a log scale; slot homes were packed offline so molecule ink never touches during motion, and joining or leaving molecules grow or shrink over `UI_HCHO_GROW_TIME`, never popping.
- Native resolution: 400 Ã— 300, landscape. Present at integer pixel scales with letterboxing.
- The target panel (Waveshare ESP32-S3-RLCD-4.2, ST7305) is 1-bit black/white. Draw only pure black (ink) and pure white (paper); there is no grey, so chart fill is paper. Under ESPHome, LVGL renders RGB565 and the display driver thresholds to 1 bit; the simulator does the same (luminance above half is paper). Preserve hard opaque transitions; avoid dither, alpha fades, or intermediate tones.
- The simulator maps ink/paper to display tones only at presentation: defaults `#303030` / `#c6c6c6`, overridable with `--ink=RRGGBB --paper=RRGGBB` or `ATMOS_INK` / `ATMOS_PAPER`.
- Scene and transition buffers are 15 KB I1 frames. The transition compositor uses integer fixed-point maths only; other model/artwork maths is single-precision `float`, with active-time timestamps kept in `double`.
- Target animation cadence is 40 fps on desktop. Measure hardware separately.
- Present completed frames from an offscreen Windows bitmap in one copy. Do not clear the visible display to black between frames. Render the initial LVGL frame before showing the window.
- Boot: the ST7305 driver and the atmos component set up at `HARDWARE` priority, ahead of the sensors, Wi-Fi and the API, so the splash appears first (576 ms after ESPHome starts on the RLCD; the rest is the driver's panel reset and sleep-out waits, kept at reference values). The device skips the boot-time PSRAM test (`CONFIG_SPIRAM_MEMTEST: n`). The panel's memory is blanked before Display On, then `atmos_show_splash()` draws the device name (largest font that fits) and the statement "Visualizing Air Quality" over the "Made for ESPHome" badge. The UI waits until the device is connected (Home Assistant API client, else network; `splash_timeout`, default 20 s), then `atmos_init()` opens the first page from the splash with the overview's portal, zooming into the badge's house logo. The simulator holds the splash for `--boot=ms` (default 1500). Keep the splash cheap: text plus the packed badge spans, no LVGL shapes.
- Page order (`page_order` in `atmos.c`, exposed as `atmos_page()`) groups pages from "open a window?" to comfort: overview, CO2, gases, formaldehyde, particles, climate. Navigation, automatic cycling and keys 1–6 follow it; scene numbers stay fixed identifiers (0 overview, 1 CO2, 2 particles, 3 gases, 4 climate, 5 formaldehyde). Automatic cycling (from `CYCLE_FIRST`, CO2) never visits the overview; the overview is a detour that resumes the cycle after its anchor (the last page shown): the right key after a page's last reading opens it and from there the page after the anchor, once per run of presses (later page ends go straight on until a hold passes without a press) (the left key always steps back to the previous reading, skipping the overview, from the overview the anchor's last); the reading select's "Overview" option (`atmos_select_overview()`), after which cycling continues after one hold.
- Low light (`atmos_set_low_light()`, from `atmos_led`'s auto-dimming ambient sensor: dark within 10 % of `dark_value`, lit again from 30 %, whatever the auto-dimming switch) mutes alert sounds (a cycle change is announced once lit). With overview in low light on (`atmos_set_overview_dark()`, the `overview_low_light` switch, key O; key L fakes low light) it parks on the overview: at the next hold end while cycling, at once otherwise, and again one hold after a manual visit (also with cycling off); alerts do not override it. Lit again, a parked display leaves after one hold: the page after the anchor (cycling) or the anchor (not). Low light is not exposed to Home Assistant (recorder).
- Transitions are chosen by the page being left, so any page can be reached from any other (`transition_effect()` in `atmos.c`). Each page opens onto the next through its own artwork: overview by icon handoff (the destination's effect from its tile icon), CO2 by zooming into one of its visible bubbles (bubble portal), particles by dust bloom (its largest specks swell into openings onto the next page, then a jittered grid of blooms covers the frame), gases by ribbons swell (its ribbons, continued across the frame at the ribbon gap, thicken from the middle lane outward), climate by droplet fall (a droplet falls onto its humidity icon and the splash opens the next page), formaldehyde by atom portal (an oxygen atom's ink swells over the frame and opens like an iris). Keep transitions anchored in artwork rather than generic slideshow wipes.
- Each transition rasterises its two scenes once, at its first frame (for device speed): the outgoing scene at the transition's start time and the incoming scene at its end time, so artwork is still during travel and live drawing resumes without a jump. `prepare_effect()` runs right after the outgoing snapshot is rasterised and takes its anchors (bubble, dust specks, ribbon line, droplet icon, oxygen atom) from that drawing. Scene holds default to 6.5 seconds (`atmos_set_hold()`, 2–600 s, a Home Assistant number on the device); transition durations per departing page are in `transition_duration()` (1.3–1.6 seconds). Timing may be deliberately tuned for a requested animation change.
- Navigation during movement queues the latest requested destination. Pause/minimize freezes motion and sampling time.
- History starts empty, retains a span of two minutes by default (`atmos_set_history_window()`, 1 min to 24 h, a Home Assistant number on the device), samples every 2 active seconds at first, stretching with the history held (about 30 samples across it) up to span/60, and never invents historical readings. A reading linked with `startup_delay: true` (`atmos_set_startup_delay()`; for the SEN6x, which reports nothing for about a minute after boot) charts from its first valid sample: the chart waits empty at "LAST 0 SEC" until the sensor reports, then its trace rises in. Shrinking the span discards older samples; growing it lets the chart fill. Scenario changes preserve the existing samples.
- Badge ratings are bands (`atmos_set_bands()`: range, any text, severity level, alert flag, optional LED colour and overview marker), with Good/Fair/Poor defaults from `ui_theme.h` for air-quality readings. Temperature, humidity and pressure are comfort readings with their own bands (Cold/Cool/Mild/Comfy/Warm/Hot, blue to orange; Dry/Fresh/Ideal/Humid/Damp, sand to deep teal; Low/Normal/High in sky whites): they never alert (no overview warning, alert focus, sounds or `alert_active`, whatever the YAML says) and stay out of the overview's rating and LED colour (`comfort_reading()`). Band text must fit the badge's rating box at 16 px (the self-test checks the defaults; about 8 characters); the device's `ratings:` YAML replaces them per reading, and its `sensors:` YAML links any ESPHome sensor to each reading (through `atmos_set_readings()`). Readings can be selected by number (`atmos_select_reading()`, the Home Assistant drop-down).
- Alerts: a band's `alert` flag (default Poor only; YAML default level ≥ 2) raises the overview's warning and `atmos_alert_active()` (the device's `alert_active` binary sensor). With alert focus on (`atmos_set_alert_focus()`, the `alert_focus` switch, key P), automatic cycling visits only alerting readings in page order (`auto_next()`): the hold is split between a page's alerting readings, other pages are skipped, a page that alone alerts restarts its hold. The hold's items are fixed when it starts (`hold_items`), so a reading clearing mid-hold keeps its page for the full hold. Manual navigation is unaffected and returns to the alerts after one hold. The overview stays out of the alert cycle.
- Alert hysteresis and sounds: every reading joins the debounced alert set after alerting for `alert_enter` (default 60 s) and leaves it after `alert_leave` (180 s) clear, in active time (`atmos_set_alert_times()`, global for now). The focus cycle and `atmos_alert_active()` use the debounced set; badges and the overview warning stay raw (`atmos_alert_raw()`). With alert focus and alert sounds on (`atmos_set_alert_sound()`, the `alert_sound` switch, key M), `atmos_poll_event()` returns `ATMOS_EVT_ALERT_START` where automatic cycling enters the alert-focus cycle (that transition's start, or a re-hold of the only alerting page) and `ATMOS_EVT_ALERT_CLEAR` where it returns to the normal cycle; START is skipped for `alert_sound_cooldown` (20 min) after a CLEAR. Turning focus off resets silently. The device fires `on_alert_start`/`on_alert_clear`; the simulator plays `esphome/sounds/alert.wav` (a WAVE resource). Sounds are 16-bit mono 16 kHz WAV made with `esphome/sounds/prepare_sound.py`; there is no clear sound yet. The audio hardware (ES8311 on I2C 13/14 at 0x18, I2S MCLK 16, BCLK 9, LRCLK 45, DOUT 8, amplifier enable GPIO46) is configured in YAML, not in the component.
- Status LEDs (`components/atmos_led`): an ESPHome addressable light (our hardware: `esp32_rmt_led_strip`, WS2812B, 4 LEDs, GPIO2) shows the colour of the rating on screen, `atmos_led_reading()` of the scene (the overview's worst). Each band's `led_color` (YAML) sets it; default by level (0 green, 1 amber, 2+ red). On a page transition the LEDs fade out over its first half and into the destination's colour over its second (`atmos_transition_progress()`); a colour change on a still page (another underlined reading, a rating change) cross-fades, eased, over `fade_time` (800 ms, the underline and chart blend time). `atmos_led` is itself a brightness-only light (Home Assistant: power and a brightness slider, which scale the colour); the strip light is internal, held on at full brightness, and flagged effect-active so it never writes its own colour. Optional `auto_dimming` limits the output by an ambient sensor (the device: LDR divider on GPIO3's ADC, 1.7 V lit room to 3.1 V dark) down to `min_brightness` (13 %, below which the WS2812s show no colour), with an HA switch; it never changes the light entity, so the recorder sees only user changes. The simulator has no LEDs.
- Demo readings, derived PM values, and warning cutoffs are illustrative. Keep sensor units and the real-reading entry point intact.

## ESPHome integration: rules that keep the code portable

The device build is an ESPHome external component, so `atmos.c` must compile with ESPHome's toolchain and ESPHome's generated `lv_conf.h`, not ours. These rules come from compiling the UI against ESPHome's configuration:

- **No custom compiler flags.** ESPHome passes `build_flags` to every file in the firmware (ESPHome, ESP-IDF, LVGL), so a code-generation flag such as `-fsingle-precision-constant` cannot be relied on. Write `float` literals with an explicit `f` suffix (`0.5f`, `1.4f`, `UI_CO2_FAIR 800.0f`); unsuffixed literals are `double`, which the ESP32-S3 computes in software. Use `double` only for unbounded active-time timestamps (`t`, `sample.at`, chart time axes) and wrap time-based phases with `fmod(t*speed,period)` before converting to `float`. `-Wall -Wextra -Werror` are for the simulator only.
- **Do not assume the display colour format.** The device and simulator now use a 1-bit I1 display, but ESPHome's LVGL component (if ever used again) supports only RGB565. Code that writes directly into an LVGL output layer, like `blit_transition()`, must handle the layer's actual `cf`.
- **One LVGL configuration.** The atmos component adds LVGL itself (`LVGL_VERSION` in `components/atmos/__init__.py`, kept equal to the simulator pin) and builds it with `desktop/lv_conf.h`, so device and simulator share every LVGL option. ESPHome's `lvgl:` component must not be added alongside it (two LVGL configurations would conflict). On the device `lv_conf.h` selects a custom allocator (PSRAM first), provided by the component: with internal-RAM `malloc`, rasterising a scene into a canvas exhausted internal RAM and LVGL's malloc assert hung until the task watchdog reset the chip.
- **LVGL version.** Keep `desktop/build.ps1` and the component's `LVGL_VERSION` in step (currently 9.5.0, as released ESPHome uses). Compile without deprecation warnings. Wrap APIs that change between versions in a small `LVGL_VERSION_MINOR` helper, as `hide_obj()` does, rather than using version-specific calls throughout.
- **LVGL setup lives in the platform layer.** `main_win32.c` (simulator) and `components/atmos/atmos_component.cpp` (device) call `lv_init()`, set the tick, create the 400 Ã— 300 I1 display in direct mode with a static 15 KB frame buffer, and run the timer handler. `atmos.c` only creates its objects, advances its model with `atmos_step()`, and accepts readings through `atmos_set_readings()`.
- **Internal LVGL APIs.** `blit_transition()` relies on `lv_layer_t` fields and `lv_draw_dispatch_*`. Recheck them whenever the LVGL version moves; the self-test fails if the presented transition differs from the composed frame.
- **ST7305 driver.** Use the local copy in `components/st7305_rlcd` (Apache-2.0, modified). The device flush calls `load_rows_i1()` to rearrange only the redrawn areas of the 1-bit frame into the panel's 2Ã—4 block layout (about 2.5 ms for a full frame), growing a dirty window; `present()` packs that window into a DMA buffer and a push task sends it by queued DMA (the CPU renders meanwhile). The driver adds its own SPI device to the bus ESPHome's `spi:` component initialised (SPI2, else SPI3) and drives CS and DC itself. Panel memory is 200 rows (2Bh, one per pair of screen columns, left to right, the order the panel refreshes in) of 25 column units (2Ah, 3 bytes = 12 screen rows); MADCTL MX=1 fills a column window from its end address, so unit u is at `col_end - u` (getting this wrong drew partial updates at mirrored heights). `partial_updates: false` sends whole frames. The conversion is checked at start-up against the driver's pixel lookup tables. Its bulk RGB565 `draw_pixels_at()` remains for any 16-bit use; the stock per-pixel path's `Color::is_on()` treats any non-black pixel as ink.
- **SCD30 driver.** `components/scd30` is ESPHome 2026.9.1's SCD30 component, modified: at setup it reads the sensor's stored automatic self-calibration (ASC) setting and writes it only if it differs, so reboots never resend it (re-enabling ASC may restart its 7-day initial period). `apply_automatic_self_calibration()` changes it at run time (the device's "CO2 Automatic Calibration" switch). `ambient_pressure_compensation_source` (YAML) names a pressure sensor in hPa (the BMP581 on the device); its reading is sent whenever it moves by 1 mbar (700–1400 mbar, overriding altitude compensation). Forced calibration is guarded: `start_calibration()` (the "Calibrate CO2" button) waits until CO2 and humidity hold within `co2_spread`/`humidity_spread` for `settle_time` (default 20 ppm, 2 %RH, 10 min), counting only from 2 min after any measurement restart (boot, ASC or pressure write, calibration), applies `reference` (420 ppm), then averages one minute after the post-calibration dip and reports "Calibrated" or "Check reading" (±30 ppm) on the `calibration: status:` text sensor; it times out after `timeout` (60 min); `cancel_calibration()` stops it. Re-sync with upstream when ESPHome moves.
- **Windows build paths.** ESP-IDF's toolchain exceeds the 260-character path limit when Windows long paths are off. Use `ESPHOME_ESP_IDF_PREFIX=C:\ESPHome\idf` and `esphome: build_path: C:/ESPHome/build/<name>` (as `esphome/bench.ps1` and `atmos-bench.yaml` do) rather than changing system settings.
- - **Pre-rendered transitions.** In automatic cycling, `prerender_step()` rasterises the next transition's snapshots during the hold, one per step, after the last history sample before it. `data_version` must be bumped by anything that changes displayed data (samples, readings, selections), or a stale snapshot will be used. Manual navigation renders the snapshots at the transition's first frame.
- **Clip-aware redraw.** When the clip area lies inside `animated_area(scene)` widened to whole bytes (LVGL rounds redrawn areas on the 1-bit display to multiples of 8 px in x and clears them first; until 2026-11-20 this made every still frame redraw its whole scene), `draw_animated()` runs only that scene's artwork function over that widened area, so static content inside it must be drawn by that function. The self-test's partial-versus-full check enforces this; it caught the Gases box overlapping the history panel.
- **Direct 1-bit fills.** `rect()` with radius 0 on an I1 layer writes bits directly (`direct_fill()`), after `sync_layer()` runs any queued LVGL tasks so ordering is kept. LVGL draw tasks cost a heap allocation and dispatch each, which dominated device frame time for span-built artwork. Prefer spans over many tiny LVGL shapes in hot paths.
- **Guard float-to-int casts.** NaN or huge values cast to `int` differ by CPU (x86 gives `INT_MIN`, Xtensa `INT_MAX`) and can overflow later arithmetic. A NaN ribbon tip crashed the device while the simulator looked fine. Clamp inputs to `pow`/`sqrt` and reject far-off coordinates before arithmetic.
- **Panel refresh and TE.** The ST7305 refreshes on its own clock: `refresh_rate` (16, 25.5, 32 or 51 Hz; FRCTRL B2h with OSCSET D8h, datasheet v0.2) defaults to 32 Hz, which measures 34.2 Hz (29.2 ms) on our panel. The Waveshare value (B2h=0x02) was 25.5 Hz, so frames above about 25 fps were dropped; 51 Hz flickers and turns black grey with the reference drive settings. `te_pin` (GPIO6 on the RLCD) takes the panel's tearing-effect output: its rising edge starts the vertical blank, and the push task sends each frame at its target pulse, so writes never tear (a 15 KB push takes 3.6 ms, faster than the scan). With `te_pin`, `frame_te_()` shows a frame every `div_` refreshes: `frame_period` rounded to whole refreshes (29 ms allows every refresh; 59 ms every second), every refresh only for a scene or transition whose frames cost under 80 % of one (decided as it starts, demoted on a late frame), else every second; the model steps by the refreshes between frames, and the next frame renders while the previous push waits and runs. Without `te_pin` frames follow `frame_period` as before. `display_test: true` replaces the UI with a counter, a stepping box, a sweeping full-height bar and full-page inversions to check panel speed and tearing on camera. The simulator's `--hw-pace` does not yet round frame times to whole refreshes.
- **SPI clock.** The benchmark runs the ST7305 at 40 MHz (reported working by a community build; artefacts near 60 MHz). Verified clean on the real panel on 2026-10-30; if artefacts appear, fall back to 20 MHz or 10 MHz. At 10 MHz the push is 12.6 ms per frame instead of 3.6 ms.
- **Redraw only what moves.** Still scenes invalidate only `animated_area(scene)`. Data changes redraw only their screen band (`dirty_bands`): a history sample the history panel, readings the header and body (the demo data marks the same), a Wi-Fi bar change the header; selection blends (underline, chart, PM) the body and panel while they run. `draw_scene()` draws only the bands its clip area touches (`band_hit()` guards in `detail_header()`, the page bodies, `history_panel()` and `history_graph()`), so anything drawn must stay inside its band. Whole-frame redraws (`full_dirty`) are left for transitions, the first frame of a reading selection (badge, underline and chart all change), settings (units, theme, rating bands) and the overview, which has no bands. When adding motion, extend that scene's area. The self-test fails if anything animates outside it or if a band redraw differs from a full redraw. The particles scene (dotted perspective floor with drifting dust, sized and counted from PM1/2.5/4/10) advances its drift in whole ticks and redraws only `UI_PM_FIELD_FPS` (20) times a second.
- **Per-frame work is the bottleneck on device, not LVGL's pixel fill.** The scene draw functions run in full even when LVGL clips to a small area, so keep per-pixel loops free of trig and other calls that depend only on the frame or column; compute those once per frame.
- **Frame-rate cap.** The device draws at most one frame per `frame_period` (with `te_pin`, rounded to whole panel refreshes; see above). Frames run from a scheduler timeout, not `loop()` or a high-frequency loop request, so the loop task sleeps between frames and Wi-Fi, the API and sensors get the CPU. The report line's "UI busy" gives the CPU share; 17 fps leaves about a third idle, 20 fps a quarter, 30 fps almost none.
- **Memory.** All frame buffers are 1-bit: LVGL's display frame (15 KB), two scene canvases and the transition frame (15 KB each), the panel buffer and the DMA push buffer (15 KB each), all in internal RAM. LVGL's own allocations (draw tasks, layers, glyph caches) go to PSRAM on the device.

## ESPHome dashboard (OTA from the server)

The ESPHome Device Builder at `10.0.0.82:6052` holds the device's `atmos.yaml` (the device is `atmos`, 10.0.0.230) and its secrets, and builds the component from GitHub at the commit pinned in `external_components` (`github://DexiTheOne/atmos-lvgl@<commit>`). To ship firmware: commit and push, re-pin that commit, then install over OTA. Commit as the git identity `atmos` (`git -c user.name=atmos -c user.email=atmos@localhost commit ...`); this shell has no global identity.

Policy: talk to the dashboard only through `esphome/dashboard.py`, its WebSocket API client. Never open the dashboard's web page (browser or in-page scripts) and never call its HTTP endpoints directly (curl, fetch, scraping). If a needed command is missing, add it to `dashboard.py` (command names come from the dashboard's own API, e.g. `devices/get_config`, `firmware/install`) rather than writing a one-off client.

```powershell
.venv-esphome/Scripts/python.exe esphome/dashboard.py list
.venv-esphome/Scripts/python.exe esphome/dashboard.py get atmos.yaml > atmos.yaml   # edit, then:
.venv-esphome/Scripts/python.exe esphome/dashboard.py put atmos.yaml atmos.yaml
.venv-esphome/Scripts/python.exe esphome/dashboard.py install atmos.yaml           # OTA, streams the build log
.venv-esphome/Scripts/python.exe esphome/dashboard.py call devices/list '{}'
```

It needs `websockets` in the venv (`.venv-esphome/Scripts/python.exe -m pip install websockets`). The dashboard has no authentication; `ATMOS_DASHBOARD=host:port` selects another server. Edited configs live on the server only; keep secrets there.

## On-device frame-pacing benchmark

`esphome/` holds an ESPHome external component (`components/atmos`) that copies the UI sources and `lv_conf.h` from `desktop/` at build time and owns LVGL, plus `atmos-bench.yaml`, which runs the UI on a bare ESP32-S3 (currently a Seeed XIAO ESP32-S3 on COM12) through the real device path: LVGL renders a 1-bit frame, the ST7305 driver rearranges the redrawn rows, then a full SPI push to unconnected pins. No panel is needed. `atmos-rlcd.yaml` runs the same benchmark on the real Waveshare ESP32-S3-RLCD-4.2 panel (on COM3; display pins SCK 11, MOSI 12, CS 40, DC 5, RST 41); select it with `-Config atmos-rlcd.yaml`. From the project root:

```powershell
./esphome/bench.ps1 -Port COM12 -Seconds 120
```

The first run installs ESP-IDF (several minutes). Results go to `esphome/bench.log`: every 10 s and after each transition, the component logs fps, frame interval (average and maximum), late frames (interval over 1.5 frame periods), and per-frame render / convert / push times (render = LVGL drawing, convert = ST7305 layout, push = SPI), separately for still scenes and transitions. Re-measure after rendering or driver changes and record results in `esphome/README.md`. Treat these as the frame-rate truth; the desktop simulator says nothing about device speed.

These are the current product constraints, not an approval gate: explicit user changes take precedence. Update the relevant documentation when behavior or operation changes.
